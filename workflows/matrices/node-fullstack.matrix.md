# Node Full-Stack Project Matrix

Drives the generation step of `workflows/new-project.md` for the node-fullstack monorepo. The web sub-app delegates to `vue.matrix.md` or `react.matrix.md`.

## Identifier

`node-fullstack`

## Version baseline (as of 2026-05)

- Node.js 22 LTS
- pnpm 10.x
- Hono 4.x (or Fastify 5.x / NestJS 11.x)
- Drizzle 0.36.x (or Prisma 6.x / Kysely 0.27.x)
- TypeScript 5.8.x

## Defaults

| Dimension | Default |
|---|---|
| `api_framework` | `hono` |
| `orm` | `drizzle` |
| `database` | `postgres` |
| `web_framework` | (asks separately — `vue` / `react` / `none`) |
| `tests` | `vitest` |
| `contracts_package` | `yes` |

## Choices

### Choices.api_framework

#### `hono` (default)
- `deps`: `hono ^4.6`, `@hono/zod-validator ^0.4`
- Runtime adapters added per deploy target (Node, Bun, Workers). Default to `@hono/node-server ^1.13`.
- `writes`: `apps/api/src/server.ts` from `shared/snippets/node/server.skeleton.ts`

#### `fastify`
- `deps`: `fastify ^5.1`, `@fastify/cors ^10.0`, `zod-to-json-schema ^3.23`
- Replace `server.skeleton.ts` adapter section with Fastify init.

#### `nestjs`
- `deps`: `@nestjs/core ^11.0`, `@nestjs/common ^11.0`, `@nestjs/platform-express ^11.0`
- More opinionated layout — generate via `nest new` post-init instead of manually scaffolding the modules directory.

### Choices.orm

#### `drizzle` (default)
- `deps`: `drizzle-orm ^0.36`
- `dev_deps`: `drizzle-kit ^0.30`
- `writes`: `packages/db/schema.ts` (initial empty schema), `drizzle.config.ts`

#### `prisma`
- `deps`: `@prisma/client ^6.0`
- `dev_deps`: `prisma ^6.0`
- `writes`: `packages/db/prisma/schema.prisma` (initial empty schema)
- `cli`: `<pm> exec prisma init` is announced, not auto-run (interactive).

#### `kysely`
- `deps`: `kysely ^0.27`, `pg ^8.13` (for postgres)
- `writes`: `packages/db/types.ts`, `packages/db/client.ts`

### Choices.database

#### `postgres` (default)
- `deps` (driver, picked by ORM): drizzle → `postgres ^3.4`; prisma → bundled; kysely → `pg`
- `writes`: `.env.example` includes `DATABASE_URL=postgres://...`

#### `mysql`
- Drizzle / Prisma both support. Driver: `mysql2`.

#### `sqlite`
- Drizzle → `better-sqlite3`. Good for local-first.

### Choices.web_framework

The workflow asks this in Stage 1 as a separate question and recursively scaffolds `apps/web/` from `vue.matrix.md` or `react.matrix.md`.

#### `vue`
- Re-enters `workflows/matrices/vue.matrix.md` rooted at `apps/web/`.

#### `react`
- Re-enters `workflows/matrices/react.matrix.md` rooted at `apps/web/`.

#### `none`
- API-only monorepo. Skip `apps/web/`. `packages/contracts/` is still created (clients can be added later).

### Choices.tests

#### `vitest` (default)
- `dev_deps`: `vitest ^4.1`, `supertest ^7.0` (for HTTP integration tests)

#### `none`
- Omit.

### Choices.contracts_package

#### `yes` (default)
- `writes`: `packages/contracts/package.json`, `packages/contracts/index.ts` (re-exports per-feature contracts), `packages/contracts/<sample-feature>.ts` from `shared/snippets/node/feature.contract.ts` with `%FEATURE_NAME%` substituted (default sample: `user`).

#### `no`
- Skip the package. Use only when the API never has a TypeScript consumer.

## Universal writes (every node-fullstack project)

| Path | Source |
|---|---|
| Root `package.json` | Assembled — pnpm workspace, scripts (`-r typecheck`, `-r build`, etc.) |
| `pnpm-workspace.yaml` | Inline — `packages: ['apps/*', 'packages/*']` |
| Root `tsconfig.json` | `shared/snippets/config/tsconfig.strict.json` (acts as base for inheritance) |
| Root `eslint.config.js` | `shared/snippets/config/eslint.flat.ts.js` |
| `apps/api/package.json` | Assembled with chosen `api_framework` + `orm` deps |
| `apps/api/src/server.ts` | `shared/snippets/node/server.skeleton.ts` |
| `apps/api/src/shared/http/errors.ts` | `shared/snippets/http/errors.server.ts` |
| `apps/api/src/shared/middleware/request-id.ts` | `shared/snippets/node/request-id.middleware.ts` |
| `apps/api/src/config/env.ts` | Inline — typed `process.env` wrapper |
| `apps/api/.env.example` | `shared/snippets/config/env.example` with `%API_BASE_VAR%` → `PORT`; plus `DATABASE_URL`, `CORS_ORIGIN` lines |
| `packages/contracts/<sample>.ts` | `shared/snippets/node/feature.contract.ts` with `%FEATURE_NAME%` substituted |
| `apps/web/**` (when `web_framework` ≠ none) | Generated by the chosen web matrix, rooted at `apps/web/` |
| `tooling/tsconfig/base.json` | Optional — `extends` chain that both apps reuse |

## Post-init CLI

| Choice | Command | Mode |
|---|---|---|
| always | `pnpm install` | auto |
| `orm: drizzle` | `pnpm --filter db drizzle-kit generate` | announce |
| `orm: prisma` | `pnpm --filter db prisma init` | announce (interactive) |

## Feature exemplar (show inline; do not auto-write)

For each API feature requested (substituting `%FEATURE_NAME%`, `%FeatureName%`):

- `packages/contracts/%FEATURE_NAME%.ts` — shared DTO + create/update body schemas (copy from snippet)
- `apps/api/src/modules/%FEATURE_NAME%/%FEATURE_NAME%.route.ts` — transport: parse params with `zValidator`, delegate to service
- `apps/api/src/modules/%FEATURE_NAME%/%FEATURE_NAME%.service.ts` — business rules
- `apps/api/src/modules/%FEATURE_NAME%/%FEATURE_NAME%.repo.ts` — DB access (via Drizzle/Prisma/Kysely from `packages/db`)
- `apps/api/src/modules/%FEATURE_NAME%/%FEATURE_NAME%.service.test.ts` — colocated test
- `apps/web/src/features/%FEATURE_NAME%/api/%FEATURE_NAME%.api.ts` — calls API using `%FeatureName%Dto` from `@<package-name>/contracts` (no manual type duplication)

Layer rules: routes only do transport, services have no transport/DB knowledge, repos are the only layer that touches the DB.
