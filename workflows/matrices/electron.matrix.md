# Electron Project Matrix

Drives the generation step of `workflows/new-project.md` for the Electron stack. The main + preload layer is invariant. The renderer delegates to `vue.matrix.md` or `react.matrix.md` based on a renderer question asked in Stage 1.

## Identifier

`electron`

## Version baseline (as of 2026-05)

- Electron 33.x
- electron-vite 2.x (build tool)
- TypeScript 5.8.x
- Node 22 LTS (matches Electron 33 runtime)

## Defaults

| Dimension | Default |
|---|---|
| `build_tool` | `electron-vite` |
| `renderer_framework` | (asks separately — `vue` or `react`) |
| `storage` | `electron-store` |
| `tests` | `vitest` |
| `updates` | `electron-updater` |

`renderer_framework` triggers a full re-entry into the chosen framework's matrix. Generation creates the renderer at `src/renderer/` using that matrix's outputs.

## Choices

### Choices.build_tool

#### `electron-vite` (default)
- `dev_deps`: `electron-vite ^2.3`, `electron ^33.0`, `vite ^8.0`
- `writes`: `electron.vite.config.ts` (three-build setup: main, preload, renderer)

#### `electron-forge`
- `dev_deps`: `@electron-forge/cli ^7.5`
- `writes`: `forge.config.ts`

### Choices.storage

#### `electron-store` (default)
- `deps`: `electron-store ^10.0`
- For user preferences. Wrap in `src/main/services/preferences.ts` with a Zod schema.

#### `none`
- App config file in `app.getPath('userData')`.

For large local data (always available regardless of `storage` choice), add SQLite via `better-sqlite3` when needed.

### Choices.tests

#### `vitest` (default)
- `dev_deps`: `vitest ^4.1`
- Two configs: main-side (Node env) and renderer-side (jsdom env). Use Vitest workspace.

#### `none`
- Omit.

### Choices.updates

#### `electron-updater` (default)
- `deps`: `electron-updater ^6.3`
- Update logic in `src/main/services/updates.ts`. Renderer subscribes to update events via a typed IPC channel.

#### `none`
- Manual update flow.

| Path | Source |
|---|---|
| `package.json` | Assembled; sets `"main": "out/main/index.js"`, includes Electron scripts |
| `electron.vite.config.ts` | Inline — three builds (main / preload / renderer) |
| `tsconfig.json` (root) | `shared/snippets/config/tsconfig.strict.json` |

| `AGENTS.md` | `shared/snippets/project-docs/AGENT.md.tmpl` — `%STACK%` → `electron`, `%UI_LIBRARY%` filled from the renderer matrix's resolved `ui_library`; `%VIEWS_DIR%` / `%DATA_DIR%` / `%DATA_HOOK_PATTERN%` per renderer framework |
| `CLAUDE.md` | `shared/snippets/project-docs/CLAUDE.md.tmpl` |
| `src/main/main.ts` | `shared/snippets/electron/main.security.ts` |
| `src/preload/index.ts` | `shared/snippets/electron/preload.bridge.ts` |
| `src/preload/api.ts` | `shared/snippets/electron/preload.api.example.ts` (rename to `api.ts`, swap example methods) |

## Renderer delegation rule

After Stage 1, when `renderer_framework: vue` (or `react`) is selected:

1. Resolve `workflows/matrices/<renderer_framework>.matrix.md`.
2. Run its `Defaults` (or the user's Stage 2 customization) for routing/state/data/forms/tests/animation.
3. Generate every file the renderer matrix lists, **rooted at `src/renderer/` instead of `src/`**.
4. Adjust the renderer's `vite.config.ts` content into the renderer build entry of the root `electron.vite.config.ts`.
5. Skip the renderer matrix's `src/shared/http/client.ts` write — Electron renderer typically talks to main via IPC, not direct HTTP. If the project also needs HTTP, the user opts in during Stage 2.
6. **Skip the renderer matrix's `AGENTS.md` and `CLAUDE.md` writes.** The project has exactly one set of docs at the repo root. Renderer choices populate the root `AGENTS.md` placeholders.

## Feature exemplar (show inline; do not auto-write)

For an IPC-driven feature (e.g. "open a file picker"), generate:

- `src/main/ipc/<group>.ts` — `ipcMain.handle('<group>:<action>', payloadValidatorThenSideEffect)`
- `src/preload/api.ts` — add typed method to `DesktopApi`
- `src/preload/index.ts` — wire `<group>: { <action>: () => ipcRenderer.invoke('<group>:<action>', payload) }`
- `src/renderer/features/<feature>/...` — UI calls `window.desktop.<group>.<action>()`

Refer the user to `boundaries/electron/security-checklist.md` before completing the feature.
